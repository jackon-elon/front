# 用这个网站学习 React

先会描述交互与数据流，再逐步看实现。每一步都能在页面上观察结果。

## 1. 一张卡片由谁组成

打开作品页。ProjectCard 负责整张卡片的打开入口、标题和爱心；Poster 负责封面的图形。它们不是一张截图，而是可复用组件。页面传入哪条作品数据，组件就显示哪张卡片，这个输入叫 props。

练习：让 AI 只增大卡片下面的中文标题，并说明为什么没有改 Poster。了解组件边界和 CSS 选择器即可，不用背语法。

## 2. 点爱心发生了什么

点击爱心 → 共享状态里的收藏列表变化 → 当前按钮变为已收藏 → 顶部数量变化 → 收藏页出现同一张卡片。

三处画面共享一份状态。StudioContext 提供共享接口，studioReducer 规定如何改变数据。列表用稳定的作品 id 作为 key，React 才能识别重排前后是同一张卡片。

练习：收藏两张卡片，进入收藏页调整顺序，刷新观察是否保存。询问 AI “哪个状态是数据，哪个结果是根据数据算出来的”，不要让多个组件各存一份收藏数量。

## 3. 调色为什么立即生效

详情页色块／滑块 → 更新该作品的草稿 → Poster 收到新的 settings → CSS 变量改变 → 预览变化。

输入框和滑块的值来自 React 状态，称为受控表单。草稿按作品 id 独立存放，改一张不会改另一张。点击保存会复制一份快照，之后修改草稿不会改旧版本。

练习：保存绿色版本，再改成黄色，恢复绿色。这个流程比单独研究一种动画更能说明真实 React 应用怎样处理数据。

## 4. 页面切换与卡片移动

点击封面 → 路由决定显示哪一个详情页 → 浏览器把旧封面和新预览连接起来。TransitionLink 封装通用导航。筛选／排序时没有离开页面，useFlipList 记录卡片旧位置，再把新布局的位移交给 GSAP。

ref 保存 DOM 引用或动画对象；useLayoutEffect 在浏览器绘制前处理布局相关工作。React 不需要每一帧修改 state。动画与事件在离开页面时必须清理，React StrictMode 会帮助暴露不正确的 effect 生命周期。

练习：让 AI 调整封面展开时长，再调整列表排序时长。说清这是两个不同的操作，避免“一次改所有动画”。

## 5. 异步、弹窗和失败情况

作品通过 fetch 加载。useCatalog 处理加载、失败、重试与 AbortController 取消请求。搜索用 useDeferredValue 延后结果渲染，输入仍优先更新；目前只有六条数据，作用是展示该组织方式，不代表需要性能优化。

保存弹窗用 Portal 放到页面顶层；打开时移动焦点并锁定背景滚动，关闭时恢复焦点。减少动态效果同时尊重菜单偏好与系统设置。

练习：让 AI 增加一个保存字段，先指出它如何流经表单、类型、保存快照、存储恢复和收藏展示。这能练习跨组件修改，避免只改了输入框而忘记保存逻辑。

## 需要认识的文件类型

- `.tsx`：TypeScript 加 JSX，写组件的结构和交互。
- `.ts`：数据类型、规则和可复用逻辑。
- `.css`：样式、响应式布局、视觉动画。
- `.json`：静态作品数据。

TypeScript 是带类型检查的 JavaScript，这里的作用是检查作品 id、设置、组件输入和状态操作。项目使用 Vite，不需要 Next.js。等需要账号、数据库、服务端渲染时，再扩展服务端架构。
