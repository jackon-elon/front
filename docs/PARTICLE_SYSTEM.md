# 实时粒子系统：效果背后的职责

这一版把原先按公式播放的粒子动画升级为保留运动状态的 GPU 模拟。Three.js 的 GPUComputationRenderer 提供反馈纹理框架；项目自己定义三种目标形态、受力、阻尼、位置积分和最终显示。它没有自研渲染器，也没有完整流体求解器。

## 可以亲手验证

打开粒子实验，切换球体、螺旋、涡环。运动开启时，同一批粒子逐渐移向新形态；暂停时选择新形态，会显示其静态形状。

鼠标进入粒子体积，选择“推开”或“吸引”。它不是移动摄像机造成的假象：指针投影到穿过对象中心、面向摄像机的平面，转为模型局部坐标，再进入力场计算。移开鼠标后粒子带着惯性返回目标形态。兼容模式不支持这个力场，页面会明确提示。

保存实验再恢复，会恢复形态和力场。旧版浏览器存储没有这两个字段时，自动使用球体与推开，不清空已有收藏。

## 核心职责与修改位置

- `src/scene/particleField.ts`：GPU 模拟和显示。`targetPosition` 定义形状；`velocityShader` 定义回归弹簧、阻尼、平滑旋流和指针力；`positionShader` 对位置积分；`drawVertex / drawFragment` 定义点大小、色彩和速度反馈。
- `src/scene/createArtScene.ts`：摄像机、对象构图、滚动形态、指针坐标转换、渲染帧率和场景生命周期。物理状态更新不触发 React 每帧渲染。
- `src/pages/HomeExperience.tsx`：滚动驱动的进度、背景颜色插值与文字渐隐。
- `src/components/ExperimentPanel.tsx`：受控参数按钮与滑块。
- `src/state/model.ts`：参数类型、默认值、旧存储迁移、保存恢复。
- `src/learning/regions.ts`：教学定位中的中文区域说明。

## 实现难点

1. 位置和速度分别保存在两组 ping-pong 渲染目标中。每个计算阶段读取上一帧纹理，写入另一张，避免同时读写同一个缓冲区。
2. 三个目标形态共用粒子种子与身份。重组只改变回归目标，原有速度继续保留，因此不是换一批点后淡入淡出。
3. 模拟按固定 1/60 秒更新，每次最多补三个步长；超长间隔丢弃，避免后台恢复或低帧率导致爆炸。显示帧率可以独立为 30 或 60。
4. 指针先经过摄像机射线、世界平面，再转到局部坐标；对象移动缩放或相机改变后，力场仍位于光标处。
5. 减少动态效果时停下力场和自主运动，仍可通过滚动和形态按钮观察静态构图。模态窗口打开时不施加指针力。
6. 离开页面释放计算材质、种子纹理、位置／速度渲染目标、绘制几何、材质、环境贴图、renderer、RAF 和事件监听。

## 性能与实际边界

桌面初始 128×128＝16,384 个模拟状态；手机初始 64×64＝4,096 个。密度只改变绘制数量，节能模式绘制预算为原有的 35%、像素比为 1，并限制 30 FPS。计算纹理尺寸在场景创建时确定，调整密度不会降低模拟状态数量。平衡模式在持续慢帧时逐级降低渲染像素比，最低为初始像素比的 60%；这不保证每种设备都能达到目标帧率。

粒子是独立受力点，没有粒子之间的碰撞、邻域作用、压力／粘性求解。旋流来自光滑向量场的旋度，不是引用一个噪声库，也不是完整流体动力学。鼠标投影使用中心平面，交互是二维指针驱动的三维力场，不是精确表面拾取。教学定位使用近似体积范围。

缺少浮点颜色缓冲支持或初始化失败时，使用相同目标函数的解析形态动画。完全缺少 WebGL 时，页面使用原有降级内容。需要更广泛的真实硬件测试才能评价跨设备稳定性。
